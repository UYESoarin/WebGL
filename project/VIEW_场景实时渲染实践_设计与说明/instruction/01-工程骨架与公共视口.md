# 01｜工程骨架、场景生命周期与公共视口

## 本阶段目标

先建立可运行的“空壳平台”：首页、场景选择、加载状态、统一 Canvas、四个占位场景、Blender 风格相机操作、退出清理。暂时不做复杂 Shader。

## 1. 工程初始化

建议依次完成：

```bash
npm create vite@latest view -- --template react-ts
cd view
npm install three @react-three/fiber @react-three/drei zustand
npm run dev
```

后处理包等到需要 Bloom 时再安装。先锁定依赖版本并提交 lockfile。

## 2. 最小运行结构

- `App`：页面状态和 UI 布局。
- `sceneRegistry`：场景元数据和动态 import。
- `SceneController`：idle/loading/active/error 等状态转换。
- `SceneViewport`：只创建一个 Canvas。
- `CameraController`：默认视角、鼠标映射和 reset。
- `Scene`：只返回当前场景的 Three 对象树。

先用四个不同颜色/几何体的占位场景，验证场景系统而不是先制作资产。

## 3. Blender 风格相机

R3F + Drei 可使用 OrbitControls。核心映射思路：

```tsx
<OrbitControls
  makeDefault
  enableDamping
  dampingFactor={0.08}
  mouseButtons={{
    LEFT: THREE.MOUSE.ROTATE,
    MIDDLE: THREE.MOUSE.PAN,
    RIGHT: THREE.MOUSE.PAN,
  }}
  minDistance={2}
  maxDistance={40}
/>
```

滚轮默认承担 dolly/zoom。根据使用的 Three.js 版本检查 `mouseButtons` 类型是否需要导入 `MOUSE` 类型。右键平移时要阻止 context menu；中键在部分设备/浏览器上可能被系统拦截，应实际验证。每个场景在 registry 中提供 `camera.position`、`camera.target`、距离限制和极角限制。

重置视角不能只重置相机位置，还要同时恢复 controls.target，并调用 update。避免每次参数变化都重新创建 controls。

## 4. 场景加载与切换

建议流程：
1. 用户选中 sceneId。
2. Controller 进入 loading，禁用重复选择。
3. 动态 import 场景模块。
4. 由场景自己的资源加载逻辑加载 GLB/纹理/HDR。
5. 收到 ready 后进入 entering/active。
6. 退出时先停止动画与订阅，再卸载场景组件。
7. 释放该场景拥有的 GPU 资源；共享缓存资源不由场景直接释放。

代码层面把“代码模块加载”和“3D 资产加载”视为两个阶段。模块加载成功不代表模型已准备完成。

## 5. 加载反馈

如果 loader 能提供真实 loaded/total，可显示真实百分比；否则显示不确定进度动画。不要用 setInterval 假造 0 到 100 的进度。错误 UI 至少提供错误摘要、重试、返回选择页。

## 6. 资源释放要点

- 组件卸载：停止 useFrame 所属逻辑和 React 订阅。
- 自建监听器：useEffect cleanup 移除。
- 自建 geometry/material/texture：明确 owner 并 dispose。
- useLoader / useGLTF 缓存：注意缓存共享，不要在场景卸载时粗暴 dispose 全部缓存。
- 动态创建的 render target、后处理 pass：由创建者释放。

建议在场景切换后观察 `renderer.info`，并连续切换至少 10 次。

## 7. 本阶段验收

- [ ] 首页到四个占位场景均能进入。
- [ ] 场景可以返回和互相切换。
- [ ] 只存在一个 Canvas。
- [ ] 左键旋转、中键平移、滚轮缩放可用。
- [ ] 重置视角恢复 position 和 target。
- [ ] 加载失败有重试和返回。
- [ ] 连续切换不出现重复动画、残留监听或明显资源增长。
- [ ] `npm run build` 通过。
