# 04｜未来城市：模块化建筑、动态交通、雨雾与 Bloom

## 1. 建筑群组织

先设计道路和地标，再布置建筑。城市不是随机盒子集合：
- 道路/主轴提供透视引导；
- 地标建筑作为视觉焦点；
- 中高层建筑形成轮廓节奏；
- 远景建筑降低细节和亮度；
- 窗灯和广告牌作为局部高亮，不要所有表面都发光。

建筑模块可参数化：高度、宽度、层数、窗格数量、灯带颜色、顶部轮廓。重复模块使用 InstancedMesh 或合并几何体。

## 2. Emissive 与 Bloom 的区别

Emissive 材质让表面在渲染中表现为自发光颜色；Bloom 是后处理，它从高亮区域提取亮部、模糊扩散，再合成回原图。仅设置 emissive 并不自动等于 Bloom。

典型 Bloom 流程：
1. 渲染场景到颜色缓冲。
2. 根据亮度阈值提取高亮像素。
3. 对高亮区域进行多尺度模糊/降采样模糊。
4. 将模糊结果与原图按强度合成。
5. 进行色调映射和输出颜色空间处理。

调试时先只保留一个发光物体，观察阈值、强度和 radius，再扩展到城市全场景。过强 Bloom 会吞没建筑轮廓、让文字不可读。

## 3. 动态交通

使用 `CatmullRomCurve3` 等曲线定义道路/飞行路径。车辆沿路径参数 t 前进：
- `position = curve.getPointAt(t)`；
- `t = (t + speed * deltaTime) % 1`；
- 朝向可由 `getTangentAt(t)` 计算，并转换为模型朝向。

多辆车使用不同初始 phase。若数量较多，使用 InstancedMesh 并按路径更新矩阵。

## 4. 雨与湿地

初级雨滴：Points 粒子向下运动，越界后重置；粒子可加轻微横向风。地面湿润感可通过更低 roughness、更强 specular/环境反射近似，但没有真实反射环境时不要期待镜面级效果。

高级雨滴、屏幕水滴和反射需要额外渲染/后处理成本，列为 P2。

## 5. 雾与城市氛围

Fog 统一远景色彩，局部体积雾可用低分辨率透明平面/粒子近似。注意透明层过多会带来排序和 overdraw 问题。

## 6. 参数建议

- neonIntensity：发光强度；
- bloomStrength / threshold：Bloom 强度与阈值；
- trafficSpeed：交通速度；
- rainAmount：雨粒子数量；
- fogDensity：雾浓度；
- timePreset：夜景/深夜/黎明。

## 7. 验收

- [ ] 建筑有主次和远近层次，地标清晰。
- [ ] emissive 与 Bloom 分工明确。
- [ ] 交通沿路径运动，方向正确且不跳变。
- [ ] 雨量参数影响粒子数量或强度。
- [ ] 低画质可以关闭 Bloom/减少雨粒子。
- [ ] Bloom 不导致全屏泛白和重要轮廓丢失。
