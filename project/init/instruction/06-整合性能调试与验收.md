# 06｜整合、性能、调试模式与最终验收

## 1. 集成顺序

1. 先冻结公共场景接口和 sceneId。
2. 一个场景一个场景接入共享 SceneViewport。
3. 确认每个场景都能 onReady / onError。
4. 接入场景参数 schema 和 UI 控件。
5. 最后接入后处理、调试模式和质量档位。

不要四个场景同时改动公共接口。公共接口变化必须先更新类型和示例场景，再逐个迁移。

## 2. 调试模式对象选择

典型流程：
1. 鼠标点击 Canvas。
2. 将屏幕坐标转换为 normalized device coordinates（NDC）。
3. Raycaster 从相机发射射线。
4. 与登记为 selectable 的对象集合求交。
5. 选中对象后显示名称/属性。
6. 用户切换 translate / rotate / scale。
7. TransformControls 附着到选中对象。
8. 变换完成时更新调试状态；退出调试时 detach。

避免对场景所有 mesh 无差别 raycast；只对可交互集合检测。拖动 TransformControls 时暂停场景点击拾取，防止事件冲突。UI 面板交互不应穿透到 Canvas。

## 3. 参数架构

公共参数：quality、debugEnabled、showHUD、camera sensitivity。
场景参数：每个场景独立 schema，例如 fishSpeed、windStrength、bloomStrength。

建议将参数分为：
- **运行参数：** 直接更新 uniform、实例数量或动画速度。
- **重建参数：** 变化后需重新生成几何体/分布，更新时应提示可能短暂卡顿。
- **调试参数：** 只在开发模式出现，不进入普通用户界面。

## 4. 性能检查

每个场景至少记录一次：
- 目标设备与浏览器；
- 分辨率和 DPR；
- 平均/最低 FPS 或 frame time；
- draw calls；
- triangles；
- 粒子/实例数量；
- 是否启用阴影、Bloom、雾；
- 场景加载时间。

优化前后使用同一设备、同一视角、同一质量档位对比。不要只凭“感觉更流畅”宣称优化成功。

## 5. 常见问题排查

| 现象 | 可能原因 | 排查方向 |
|---|---|---|
| 进入场景黑屏 | 模块加载错误、相机方向、灯光、shader compile | 控制台、onError、相机 target |
| 模型粉色/黑色 | 贴图路径、材质、色彩空间 | Network、材质 map、colorSpace |
| 透明光束消失/穿插 | 深度写入、排序、材质 side | depthWrite、renderOrder、透明层数 |
| Bloom 全屏泛白 | 阈值低、强度高、色调映射 | threshold/strength/exposure |
| 场景切换越来越卡 | GPU 资源未释放、监听器残留 | renderer.info、cleanup、缓存所有权 |
| 鱼群抖动 | deltaTime、速度上限、朝向插值 | 固定/平滑更新、lerp、时间步长 |
| 风动整树摇摆 | pivot/顶点高度权重错误 | 模型原点、local/world space |
| 鼠标操作不符合预期 | mouseButtons 映射或 DOM 事件冲突 | 浏览器实际测试、contextmenu |
